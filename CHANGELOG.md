# Changelog

## Unreleased
- **Fix: private repository not recognised by the update check.** When GitHub answers with its (SSO) sign-in page instead of `latest.json`, the error now says the repository is private, and the **Sign in to GitHub** button appears. It also appears for the "sign-in" wording, which wasn't matched before.
- **Fix: DOORS Next with a global configuration found 0 modules (HTTP 400).**
  - **Configuration field:** a GCM web link (`…/gc/web/projects/…#action=gc.viewConfiguration&path=…`), a DOORS Next link with `oslc_config.context`, or a URL-encoded value is now turned into the configuration URI (`…/gc/configuration/51068`). This applies in Settings when pasted, and to values already saved. Pasting a GCM link into the server field sets the configuration and leaves the server unchanged.
  - **Component discovery** now runs for such global configurations as well.
  - **OSLC query fallback** sends an absolute `projectURL`.
  - **Diagnostics** show the server's own reason for HTTP errors and why the services document failed.
- **The coordinator can create custom agents.** The new `create_agent` tool defines any kind of agent: name, description, complete instructions, optional extra tools, harness and model. It can run the new agent right away. Agents are saved to your agents folder and reusable; with `keep: false` they last until the app restarts. Built-in agents and agents you wrote yourself are never overwritten. In text mode the coordinator uses `AGENT name[@harness]: description … END` blocks. TheFlashMaster's instructions describe this and say to reuse existing agents first.
- **Autopilot by default.** New chats start with Autopilot on, existing chats are switched to it once, and tool approval defaults to *Auto-approve everything*. Agents and specialists no longer stop to ask for permission. Blocked commands and read-only mode still apply. Settings → General → *Autopilot for new chats*; the per-chat toggle stays next to the chat box.
- **Text-mode tools for agents without MCP.** This covers Pi, which has no MCP, and OpenCode or Copilot with MCP blocked. Any agent whose TheFlashMaster tools aren't confirmed loaded gets a compact list of the app's tools (tasks, artifacts, progress, Jazz, DOORS Next) and can call them as `TOOL name {json}` lines. The app runs them and returns the results, for up to 12 rounds per request. Separate MCP servers (office, Context7…) can't be reached this way.
- **Fix: update check on GitHub Enterprise Cloud with data residency (`<name>.ghe.com`)** failed with HTTP 406. Those repositories are now recognised and use their API host `api.<name>.ghe.com`. Web download links are requested with `Accept: */*`, because GitHub's web server answers 406 to a JSON-only request.
- **Fix: `ERR_TUNNEL_CONNECTION_FAILED`**, where the proxy refuses to connect to a server (typically an internal server sent through the internet proxy). It now triggers the proxy fallback (system proxy, then direct), and the error explains how to add the host to *No proxy*.
- **Jazz: Basic authentication is now the default**, listed first as "Basic (default)". Installs that never changed the setting switch to Basic; an explicitly chosen method is kept.
- **Delegation without the `delegate` tool (text mode).** If the coordinator's tools don't load, delegation still works. Causes include Copilot's organisation policy *MCP servers in Copilot* being off ("MCP servers blocked by policy") or Pi, which has no MCP support. In text mode the coordinator writes `DELEGATE role[@harness]: brief` lines, the app runs those specialists in parallel and feeds their results back to it, for up to 6 rounds per request. When the tools are missing after the first reply, the coordinator is asked to re-plan in text mode instead of doing the work itself. The chat says why: blocked by policy (detected from Copilot's logs), Pi, or "run Test tool servers". A troubleshooting entry was added to the Documentation page.
- **TheFlashMaster only coordinates.** It no longer does any work itself, small tasks included. Reading or analysing code and documents, editing files, running commands, reviews and artifacts all go to a specialist through `delegate`. When no specialist fits it uses software-expert for code and analyst for anything else, and it sends incomplete results back as a follow-up instead of fixing them itself. If delegation fails, it reports the failure instead of falling back to doing the work.
- **Fix: background agents not shown as working.** A specialist waiting for a free slot (Settings → Agents → max concurrent turns) used to sit at "idle" with no activity. It now shows as running with "⏳ Queued — N/max agents busy". A specialist the coordinator waits on now runs in the coordinator's slot, so the two can no longer block each other. An agent stopped while queued no longer starts afterwards.
- **Delegation can pick the agent CLI:** `delegate` takes `harness` (copilot, opencode, pi, duo) and `model`, and warns in the chat when the requested CLI isn't available. The coordinator is told never to start agent CLIs from a shell or use its CLI's built-in sub-agents for specialist work. Agents started that way ran outside the app, without its tools ("no filesystem or shell tools exposed") and invisible in the Agents tab.
- **Fix: `ERR_NO_SUPPORTED_PROXIES`.** The proxy value (from Settings or `https_proxy`) is now normalised before Chromium sees it. That covers credentials (`http://user:pass@host:port`, answered on the proxy's sign-in challenge), paths and trailing slashes, `socks5h://` and `socks4a://`, PAC/WPAD URLs (`…/proxy.pac`, `wpad.dat`, `pac:<url>`) and lists of several proxies. When Chromium still rejects the proxy setup, requests fall back to the Windows system proxy, then a direct connection, and keep the mode that works. Settings → Network has a **Test connection** panel that shows the proxy in use and what it resolves to for an address. Copilot, npm and pip get a proper `http://host:port` URL, and never a PAC URL.
- **Fix: renaming a project** did nothing, because it used `window.prompt()`, which Electron doesn't support. It now renames inline, like chats: right-click → Rename project, double-click the name, or press F2. Enter saves, Esc cancels.
- **Fix: renaming a chat** no longer snaps back to the old name while typing. The sidebar row was a component defined inside the render function, so every update (agent status, streaming) remounted the rename field. The rename field now keeps its own state, Enter or clicking away saves, and Esc cancels. The same pattern was fixed in the Documentation page, where open troubleshooting items no longer collapse.
- **Self-update from your repository's releases:**
  - **Source:** set once in `package.json` (`flashmaster.updates.url`): a github.com or GitHub Enterprise repository, or a web folder. Settings and policy can override it.
  - **Releases** carry `latest.json`, written by `scripts/release-manifest.mjs`, now part of `npm run dist:win` and the release workflow.
  - **Download:** in the background, with SHA-256 verification.
  - **Install:** the installer runs silently and restarts the app; the portable exe swaps itself in place.
  - **Private repositories:** sign in once in an app window (SSO), or use a read-only token (encrypted).
  - **UI:** stable and pre-release channels, a sidebar pill ("Restart to update"), and Settings → About with status, progress and notes.
- **Delegation reliability (TheFlashMaster → specialists):**
  - The app's tool servers now get the essential environment (PATH, SystemRoot, TEMP, proxy…) and the bridge settings as arguments, so they work even when a harness starts them with only the variables we pass. On Windows, without SystemRoot a process cannot open sockets.
  - The forwarder uses `node:http` without the 5-minute `fetch` timeout, so long specialist runs no longer drop.
  - Long tool calls send MCP progress notifications.
  - The local bridge has no request timeouts, and transient socket errors are retried.
- **Network drops are retried:** "Connection error … other side closed (UND_ERR_SOCKET)" and similar transient errors between a harness and its model API are retried twice; the reply continues where it stopped.
- **Tools-not-loaded warning:** if an agent's harness never reached the app's tools, the chat says so. **Settings → MCP → Test tool servers** starts the servers exactly like a harness and shows what blocks them.
- **Copy code:** every code block in agent replies has a header with its language and a **Copy** button (shows ✓ Copied). Inline commands like `npm ci` copy on click. HTML in code stays escaped.
- **Chat header alignment:** Agent, Harness and Model fields and the Progress, Artifacts, Stop and … buttons sit on one line with equal heights, aligned at the top. Wrapped rows stay left-aligned when a side panel is open.
- **DOORS Next with global configurations and component streams:**
  - A global configuration (…/gc/configuration/…) reads modules across all contributing components.
  - Without a configuration, or when the global configuration has nothing for a project, every component of the project is discovered (`/cm/component/ldpc?project=…`) and read from its default stream.
  - Each module keeps its own configuration for reading and caching. The module list is grouped by component.
  - The OSLC fallback is also used when the Reportable REST API returns an empty list.
  - When nothing is found, the Requirements tab shows step-by-step diagnostics with Copy and Retry.
- **Jazz keyword search finds items across the whole project area:**
  - Words are searched with EWM's full-text search (OSLC `oslc.searchTerms`) in each configured project area, with an open/closed filter where the server supports it. Before, they were only matched against the first batch of items.
  - It falls back to local matching on servers without full-text search.
  - The "mine" filter set automatically on first load no longer narrows keyword searches.
- **Chats open at the latest message:** when the app starts and when you switch chats. The view stays pinned to the bottom while content grows (streaming, images, diagrams) unless you scroll up to read; scrolling back down re-attaches.
- **DOORS Next without the Reportable REST API:** when `/publish/modules` or `/publish/resources` returns 404, modules are listed with OSLC Query (`rdf:type=jazz_rm:Module`, configuration-aware, paged). Module contents are read through the module's `oslc_rm:uses` and each artifact's primary text and type. The choice is remembered per server.
- **DOORS Next setup accepts browser links:** paste the root or any DOORS Next link (e.g. a component dashboard).
  - The app keeps only the context root (`…/rmA1`) and takes the component and configuration from the link.
  - The component's project and default stream are resolved automatically.
  - Project discovery falls back to the Jazz process API.
  - "Test" no longer reports success when the URL points at a web page.
  - Context roots with suffixes (`ccmA1` → `rmA1`) are derived correctly.
- **Work item search:** "open" includes in-progress states. There is a fifth, minimal query form for strict servers, a clearer final error, and Jazz URLs copied from the browser are cleaned. **Test** now also runs a real search and says which query form works.
- **Jazz robustness:**
  - When a server rejects a query (for example HTTP 500 because a reportable field or filter isn't supported by that EWM version), the app retries with fewer fields, then with filters applied locally, and remembers what works.
  - Error messages now include the server's own reason.
  - Work item details fall back to basic fields, with comments fetched separately.
- **No more Electron deprecation warnings:** secrets use the async `safeStorage` API. Secrets stored by older versions are read once and re-encrypted.
- **Steering acknowledgement:** steering and queued messages show their delivery status. **sending** or **queued** turns into **delivered** when the agent receives the message, then **seen ✓✓** once the model continues with it in context.
  - Pi confirms natively when it injects the message.
  - Other harnesses count it as seen at the first output of the redirected turn.
  - The status updates live, with a short animation.
- **Chat artifacts & diff viewer:** an **Artifacts** button in every chat opens a panel with four tabs:
  - **Changes:** every file agents created or edited, captured from ACP `diff` tool content and from writes through the app. One entry per file per turn, with a +/− stat.
  - **Git:** uncommitted changes in the project folder, HEAD vs. working copy.
  - **Saved:** reports agents stored with `save_artifact`.
  - **Code:** code blocks from replies.
  - **Viewer:** side-by-side or unified diff with line numbers, word-level highlights, wrap and full-file toggles. Download the file, a `.patch`, or all changes of the chat as one patch.
- **IBM DOORS Next requirements** (Jazz Requirements Management):
  - **Sign-in:** uses the same Jazz sign-in (form, Basic, Windows or browser SSO). The `/rm` server is derived from the Jazz URL. There are an optional project filter and an optional configuration (stream/baseline/GC) for configuration-managed projects.
  - **Data:** projects come from the OSLC RM catalog. Modules and their contents (document order, sections, types, attributes, links) come from the read-only Reportable REST API, with paging. Contents are cached on disk.
  - **Requirements tab on the IBM Jazz page:**
    - module list, document view with collapsible headings, ranked search, detail panel
    - select requirements and **Analyse** with any agent, scoped to a code project and an optional goal
    - create a task, copy, open in DOORS Next
  - **Requirement retrieval tools for agents:**
    - `rm_modules`, `rm_outline`, `rm_search` (BM25 with stemming, exact id hits first, short text) and `rm_get` (full text, attributes, links)
    - agents fetch only the requirements relevant to the question, never whole modules
    - the analyst, tester, architect, reviewer, challenger, RCA and AUTOSAR agents have them
- **Your profile:** in Settings → General you can set a display name (shown instead of "You") and a profile picture. Upload, drop or paste an image; it is centre-cropped, downscaled and stored only on this PC. Without a picture, your initials appear on a colour you choose. Your avatar shows on your chat messages and at the bottom of the sidebar; click either to change it.
- **Chat management:**
  - **Right-click menus** on chats: rename, pin to top, reset context, copy as Markdown, archive/restore, delete. The same menu opens from the "…" button and the chat header.
  - Right-click menu on projects: new chat, rename, open folder, show archived, remove.
  - Chats can be renamed by double-click, F2, or the ✎ in the header. Archived chats are hidden behind "Show archived".
- **Reset context:** a ↺ button next to the chat box. The chat's agent sessions are closed and not resumed, and a divider marks the reset. Earlier messages stay visible but are no longer sent, which saves tokens when the topic changes.
- **Documentation section:**
  - Install Copilot CLI from the official GitHub release downloads (x64/ARM64), then pick copilot.exe. No winget, npm or terminal.
  - Sign in through "Open Copilot CLI" and `/login`, or with an encrypted fine-grained token (Copilot Requests permission).
  - A live setup checklist, a full user guide and troubleshooting.
  - Common unzip locations of copilot.exe are found automatically.
- **Copilot usage bar:** now always shows its state (checking, unavailable with the reason, or the numbers). It checks when a chat opens if the data is stale, finds Copilot even if it was set up after start, and reads more output formats.
- **New look:**

By default `/usage` is sent only when Copilot lists it as a built-in command, so a check never spends a premium request.

## 0.3.0 — 2026-11-13
- **Pi:** native `pi --mode rpc` adapter. Pi is now found when only `pi` is installed (no `pi-acp` needed). It streams, supports abort, reports usage, resumes sessions, and read-only mode uses Pi's read-only tool set.
- **Models:** discovered from each harness (ACP `availableModels` or a model config option; Pi `get_available_models`; `opencode models` as a fallback), cached, and suggested in the chat header, Settings → Harnesses and per-agent overrides. The selected model is applied via `session/set_config_option` or `set_model`.
- **New specialist:** 🥊 Challenger (adversarial review of plans and implementations). The coordinator and the plan workflow consult it.
- **Activity animations:** specialist list, streaming avatars, agent chips and status pills.
- **IBM Jazz fix:** login no longer uses manual redirects, which Electron cancels ("redirect was canceled"). Jazz now has its own persistent cookie session, detects login success or failure from EWM auth headers, and gives a clear error for OIDC/JAS redirects.
- **Proxy:** standard `https_proxy`/`http_proxy`/`no_proxy` are used everywhere, and the Electron binary download is repaired automatically.

## 0.2.0 — 2026-11-13
- **New specialists:** 📊 Presentation Expert (PowerPoint create/edit via the new `office` MCP server: outline, slide detail, create from a corporate template, targeted edits, tables, images, notes, native Ishikawa slides) and 🧭 NOW Analysis & RCA (NOW format, Ishikawa + 5 Whys, INCOSE practice).
- **Ishikawa diagrams in chat:** a fenced `ishikawa` block renders as a fishbone; confirmed causes are highlighted and ruled-out causes struck through. Also exported as SVG or PowerPoint shapes.
- **Bring your own agents:** an editable template, live validation, import from the editor, files or drag-and-drop, plus export and remove. Agents can declare skills that load on their first turn.
- **Progress flowchart:** per agent, it shows the plan steps (from ACP plan updates or the new `report_progress` tool), delegations as branches, approvals, the outcome and an activity timeline. Open it from chats, agent chips or the Agents overview.
- **Branding:** no third-party branding in the app; it is TheFlashMaster throughout.

## 0.1.0 — 2026-11-12
First release.

- **Harnesses:** GitHub Copilot CLI, OpenCode and Pi via ACP; GitLab Duo CLI via headless mode; an offline mock harness.
- **Projects and chats:** projects with chats, streaming, threads, reactions (✅/❌ answer approvals), @mentions and slash commands.
- **Coordination:** TheFlashMaster coordinator with delegation through the flashmaster-core MCP server, and eight specialist roles.
- **Agent control:** an agents overview with pause/resume/stop, a usage dashboard and a SQLite task board.
- **Integrations:** IBM Jazz (EWM/RTC); Vector/AUTOSAR tools (DBC, ARXML, CDD, CAPL, CANoe, DaVinci); winIDEA debugging (isystem.connect).
- **Workflow and settings:** the superpowers workflow on demand, token-efficiency engine, comprehensive settings and an enterprise policy file.
- **Pipelines:** local CI, a GitHub Actions CI on Windows and Linux, and a Windows x64 release (portable exe + per-user installer).
