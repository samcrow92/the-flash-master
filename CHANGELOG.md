# Changelog

## Unreleased
- **No telemetry and nothing sent in the background.** The app never had analytics or crash reporting; now it also stays off the network until you use a feature. Update checks, plugin update checks, Flash server submission polling and the Copilot credits timer are off by default (turn them on in Settings). Agent CLIs, MCP servers, installs, checks, hooks and the terminal get the standard telemetry opt-outs (`DO_NOT_TRACK`, Claude Code, PowerShell, .NET, npm, pip and more; your own values win). OpenCode session sharing is disabled, the Linux spell checker no longer downloads dictionaries from Google, and Context7 (a cloud service) is off until you enable it. docs/privacy.md lists everything that can still leave your computer and when.
- **Fix: the icons on a message's "N replies" chip overlapped.** The faces now sit side by side, one per author (system notes share one), with "+N" for the rest.
- **Fix: the Artifacts tab's buttons vanished after refreshing Git.** With many changed files, the list squeezed the Changes, Git, Saved and Code buttons away. The buttons now stay put and the list scrolls under them. Long repository paths are cut from the left with the full path in the tooltip, and file paths that start with a dot no longer show it at the end.
- **Fix: the message bar's buttons spilled past the chat box while an agent ran.** Steer and Queue join the row while an agent works, so Superpowers, Autopilot, Steer and Queue then show only their icons (names in the tooltips). If the row still doesn't fit (a narrow window), the drive strip and Send move together onto a second line inside the box.
- **Fix: a Duo chat showed both mode strips side by side.** With GitLab Duo selected, the Duo strip (AUTO, ECO, COMFORT, SPORT) now takes the drive modes' place. Picking Duo as the harness clears a drive mode the chat had, so a hidden mode can't keep steering the chat.
- **One automotive look for the whole message bar.** Attach, @, /, Superpowers, Autopilot, reset context, Steer / Queue and Send now share the drive strip's slanted segments. Tools stay quiet until you hover them. Superpowers (gold) and Autopilot (blue) light up with the same glint as a drive mode when switched on. Send is the accent "start" key at the end of the row.
- **Fix: project chats in the sidebar no longer expanded.** Click a project to fold its chats open or shut again, with pinned chats on top and archived ones behind a toggle. Each chat row has its menu (rename, pin, reset context, copy, archive, delete). The app remembers which projects are open, and the project of the chat you open expands by itself. Thread replies still stay out of the sidebar and open in the chat's side sheet.
- **Drive modes look like Duo's.** On every chat, LOCAL, ECO, COMFORT and SPORT now use the same slanted, car-style strip beside Send as Duo chats, with chevrons that grow with power and a glint on the mode you pick.
- **Fix: the drive modes hung under the message box and Duo's modes showed only A, E, C, S.** Everything now sits in the one row under your message. The drive modes (LOCAL, ECO, COMFORT, SPORT) are beside Send. On a Duo chat, Duo's strip takes their place with its full AUTO, ECO, COMFORT and SPORT labels. When the window gets narrow, the Superpowers and Autopilot words go first, then the mode names, and the icons stay.
- **Collapsible sidebar.** Hide it with the button next to the app icon at the top left, or Ctrl/Cmd+B, and the chat gets the width. The same button brings it back, and the app remembers your choice.
- **A cleaner, Codex-style layout.** The chat is one centred reading column. Agent replies read like a document, and your messages are a soft bubble on the right. The top bar shows the project and chat name (click either to switch chats), the Specialists and Agents pills, and the Threads, Progress and Artifacts buttons. The agent, harness and model pickers sit quietly under the message box.
  - **One floating side sheet.** Threads, Progress and Artifacts open as tabs of one glass sheet instead of fixed columns. In a wide window the chat moves aside for it. In a narrow one it floats over the chat. Esc or the X closes it.
  - **Threads open in the sheet.** A message with replies shows an "N replies" chip. Clicking it, or Reply, opens the thread in the sheet, ready to answer. The inline thread card is gone. Each thread row can still open in its own window.
  - **No chat lists in the sidebar.** The sidebar has New chat, the pages and your projects. A project row reopens the chat you last had open there, even after a restart. Other chats are in the switcher under the chat's title, with archived ones at the end, or in search (Ctrl/Cmd+K).
- **EWM folders without the command line.** `scm_list`, `scm_find_files`, `scm_read_file` and `scm_download` now work over HTTP alone: give the agent a stream, component or folder link from the EWM web UI. Folders come from EWM's own *Download as zip* (the file content service), read in memory, so no `scm.exe` is needed. With a folder link, `scm_read_file` takes a path relative to that folder (a file name is enough), and `scm_download` copies binary files such as PDFs, or the whole folder. The command line is only needed for changes (check-in, accept, deliver). The community `ewm-scm-utils` tool was checked and not used: it is a Java tool that would need IBM's client libraries on every PC.
- **Fix: GitLab Duo agents said the EWM tools (`scm_link`, `scm_list`…) were not in their tool list.** Agents now get the Jazz tools, source control included, as soon as a Jazz server or sign-in is filled in, not only with the IBM Jazz switch on. Duo specialists are told plainly that their TheFlashMaster tools are the TOOL lines in their instructions, not Duo's own tool list.
- **Fix: Duo could not open its own instructions file.** Long goals go in `.flashmaster-duo/`, which was hidden from git with a `.gitignore`, and Duo's file reader refuses ignored files. The folder is now kept out of git through the repository's local exclude file (`.git/info/exclude`) instead, and the old `.gitignore` is removed.
- **Fix: every EWM source control tool said "not configured".** Source control sat behind its own *Enabled* switch, off by default. It now runs on the Jazz connection you already have, with no setup of its own. Agents can also pass the EWM link you give them (`link`, or the URL as the stream): the server, stream, component and path come from it, and a link to another EWM server uses the same sign-in. New `scm_link` tool shows what a link points at.
- **Agents work in IBM EWM source control, not only read it.** With the Jazz sign-in already set up, agents create a repository workspace on a stream (`scm_create_workspace`), load it into a sandbox in their working folder (`scm_load`), edit files with their usual tools, check in with a comment and work item (`scm_checkin`), look at status and change sets (`scm_status`, `scm_changesets`, `scm_changeset`), comment, link or complete change sets (`scm_changeset_update`), accept incoming changes (`scm_accept`), deliver (`scm_deliver`) and discard (`scm_discard`). It all runs through the EWM SCM command line.
  - Streams change only by deliver, and deliver is off until you turn on *Agents may deliver* in Settings → Integrations → IBM Jazz → Source control; the agent must also repeat the stream's name. Read-only mode blocks every change.
  - The software expert now has the `jazz` tools for this; the coordinator already had them.
- **Fix: a local release stopped on two tests that only fail on a slow machine.** The Duo progress test checked for log lines after three 40 ms heartbeats, before a slow-starting process had written them, and the agent cleanup test ran out of time on Windows, where antivirus slows every git call. Both now wait long enough. When the checks fail during `scripts/release.py`, it says whether CI passed on GitHub for that commit and asks whether to continue.
- **Release from your own Windows machine: `py -3 scripts/release.py`.** It reads the newest release on the git remote, suggests the next version (patch, minor, major or custom), checks the setup first (Node, credentials from `gh` or `GH_TOKEN`), lets you pick the remote to release on when the repository has several (`--remote`), builds from a fresh checkout of that remote's main branch (or `--ref`) so local changes never end up in a release, runs the checks, builds the installer and portable exe, and uploads them with `latest.json` and `SHA256SUMS.txt` to a new GitHub Release, with step indicators, progress bars and a fix hint for every failure. `--dry-run` previews everything; a failed upload resumes with `--skip-build`. The release workflow skips its own rebuild when the release was already published this way. See docs/updates.md.
- **Fix: local-only agents were started on GitLab Duo and refused the work.** An agent whose instructions demand local inference (a Scout that must not send code to a hosted model) ran on whatever the chat, drive mode or default harness was, e.g. hosted Duo, and stopped with "Locality check failed". Such agents (frontmatter `local: true`, instructions that require local inference, or a delegation with `local: true`) now always run on Pi or OpenCode with a local model: the coordinator's, the agent's own, or Settings → Modes → LOCAL. They are never started on a hosted harness; with no local model set up, the coordinator gets a clear reason instead of a run that can only refuse. The agent is told what it runs on, as the launcher's evidence for its locality rule. A brief that demands local inference also goes to the LOCAL model when one is set up, and a specialist that still refuses hosted inference comes back to the coordinator with the exact local re-run, so it fixes the blocker instead of asking you.
- **Code graph: a real progress bar and loading indicator.** While graphify runs, the Code graph row shows a progress bar that follows graphify's own file count ("Scanning the code: 100 of 253 files", 38%), a sliding bar while graphify installs (with pip's current step), and a spinner on the button instead of the rotating graph icon.
  - **Fix:** with a long memory list, the Memory page squashed the knowledge panel's surroundings (the scope bar shrank to an empty sliver). Only the list shrinks and scrolls now.
- **Scan a project's code into its knowledge base with graphify.** The knowledge base strip on the Memory page has a new *Code graph* row with **Scan code**: [graphify](https://github.com/Graphify-Labs/graphify) maps the project's code locally (tree-sitter, no LLM, no API key) and its report becomes the `code-map` knowledge entry, shared in git like the others. *Open graph* shows graphify's interactive graph. Agents get the new `code_graph` tool (query, explain, path, most connected, affected) and a knowledge base build starts from the code map. The first scan installs graphify into the app's own Python environment (Python 3.11+ needed); scans only run when you press the button.
- **The coordinator runs the crew; you only hear about real blockers.** A specialist's question, blocker or failed recovery now goes to the coordinator, not to you. The coordinator answers it itself (from the brief, the project and memory), gives the specialist the missing context or a narrower task, retries it, or hands the work to another specialist, and tells you which call it made. It raises a **Needs you** card only for missing access or credentials, a choice that changes what you asked for, or a step that can't be undone. The specialist's thread shows each question and where it went. Text-mode coordinators can follow up with a specialist through `DELEGATE <role> agent "<agentId>": …`.
- **The flow always goes end to end, and you always get feedback.**
  - **Fix: specialists finished without delivering anything.** With text-mode tools (the default), a specialist whose first reply was only `TOOL` lines had that reply sent to the coordinator as its result, and its real report afterwards was dropped. Now only the task's last turn reports back.
  - **Silent specialists are recovered.** One that ends without a report, fails or crashes is first asked to deliver, then restarted on its task. One that sends nothing for twice the stuck-agent time (no tool call running) is interrupted and told to deliver what it has. The chat shows each attempt. Settings → Agents → *Recover a specialist that delivers nothing* (default 2; 0 = ask you right away).
  - **"Needs you" cards.** Questions and blockers show as a clear card in the chat: who asks, the question, why it waits, quick answers (recommended first) and a field for your own answer. Your answer goes back to the agent that asked, and a specialist's new result goes on to the coordinator by itself. Agents raise them with the new `ask_user` tool or a result with `status: needs_decision` / `blocked` (now with an `options:` line). A specialist that still delivers nothing after the recovery attempts becomes a card too: *Restart it*, *Continue without it*, or tell it what to do.
  - **The coordinator never ends a turn silently.** An empty turn gets one reminder to tell you where things stand; a second one raises a card.
- **Diagrams are mandatory in HTML reports.** Every agent, on every harness, is told that HTML files and reports it writes must include diagrams: an Ishikawa (fishbone) for root causes, plus flowcharts, timelines and sequence diagrams where they help (Settings → Agents → *Diagrams in HTML reports*, on by default).
  - New `diagram_svg` tool renders Ishikawa, flowchart, timeline and sequence diagrams as inline SVG with embedded styles, so reports open offline (no CDN, no scripts). Given a report file and a `<!-- diagram:name -->` marker it inserts the SVG itself, so agents don't spend tokens pasting SVG.
  - Fishbone cause labels now wrap instead of running across the neighbouring bone.
- **Agents are held to their deliverables, inside projects too.** After each finished turn the app itself checks the result, on every harness: a report agent (the RCA analyst) must have written an `.html` report (or an HTML artifact when it cannot write files) with an Ishikawa diagram, and any `.html` an agent points to must contain diagrams. A miss sends the agent back to finish (twice at most) before its result reaches the coordinator; the chat says so, and warns if it still falls short. Roles declare this with `requires: [html-report, ishikawa]` in their header.
  - Built-in instructions now also win over project and harness instruction files (AGENTS.md, CLAUDE.md, rules) in *Harness defaults* mode, not only in *Clean* mode.
  - The coordinator sends root-cause analyses to the RCA analyst and gives you the report path.
- **The NOW analyst is now "Structured Analysis & RCA (Ishikawa · INCOSE)".** It no longer uses the NOW format: problem definition (is / is-not), system context, Ishikawa with 5 Whys, cause verification, escape analysis and traced actions per INCOSE / ISO/IEC/IEEE 15288, always delivered as an easy-to-read `.html` report (summary card first, then diagrams and tables).
- **Clickable links to files and web pages in chat.** Web URLs, `file:///` links, Windows paths (`C:\…`), and project-relative paths in agent replies (also inside backticks) open on click: web pages in your browser, files with their default app, so an agent's `.html` report opens in the browser. Relative paths resolve inside the chat's project. Programs and scripts (`.exe`, `.bat`, `.ps1`, `.lnk`, …) are never run from a link; their folder opens with the file selected. Network (UNC) paths and other link types (`javascript:`, `data:`, …) are refused. Agents are told to end replies with a direct link to every file they create.

- **New specialist: EXAM Test Agent** (`@exam-test-agent`). It's an expert in EXAM, the UML-based HiL/SiL test automation from MicroNova used across the VW Group.
  - **What it does:** designs test cases from requirements (DOORS Next / Jazz, or attached specs), creates them in EXAM, runs suites on a system configuration and summarises failures.
  - **Creating test cases:** it uses the Test Case Generator (keyword test descriptions), or Groovy scripts run inside EXAM. The Groovy model API isn't public, so the agent first explores it with read-only scripts.
  - **What it remembers:** it saves verified facts about your EXAM setup to `exam-notes.md` in the app data folder, so later sessions don't have to find them again.
  - **New `exam` tool server (Python, no extra packages):** reaches the EXAM RESTapi plugin, using the same endpoints as MicroNova's Jenkins plugin. It can check status, start EXAM headless, load models, filter, run, wait, stop, convert reports to JUnit, give a compact results summary, generate test cases and run Groovy scripts.
  - **Without MCP:** the same tools are available from a command line. The agent's CLI gets `FLASH_PYTHON` and `FLASH_EXAM_CLI`, so it works in text mode where MCP is blocked.
  - **Automatic EXAM setup:** at start the app finds the EXAM installation and fills in the install folder. It installs the RESTapi plugin when it's missing and reports anything that's still missing.
    - **The plugin package:** the plugin is licensed MicroNova software, so it isn't shipped with the app. Set its location (company share path or http(s) URL) in Settings, or get it from a department marketplace.
    - **How it's installed:** a `.jar`, a `.zip` with `plugins/`, or a zipped p2 update site.
    - **Without admin rights:** the plugin goes into a per-user dropins folder, which the agent passes to EXAM when it starts it.
    - **The checklist** covers the installation, RESTapi plugin, license server, application server, default model and RESTapi. Use **Check** / **Set up EXAM** in Settings, or the agent's `exam_setup_check` / `exam_setup` tools.
  - **Team setup through the marketplace:** a plugin can include `exam.json` with the team's EXAM server, license server, defaults and the plugin package hosted on the marketplace server. Installing it fills in the empty EXAM settings and runs the setup. Example: `marketplace-example/plugins-src/exam-team-setup`.

Web download links are requested with `Accept: */*`, because GitHub's web server answers 406 to a JSON-only request.
- **Fix: `ERR_TUNNEL_CONNECTION_FAILED`**, where the proxy refuses to connect to a server (typically an internal server sent through the internet proxy). It now triggers the proxy fallback (system proxy, then direct), and the error explains how to add the host to *No proxy*.
- **Jazz: Basic authentication is now the default**, listed first as "Basic (default)". Installs that never changed the setting switch to Basic; an explicitly chosen method is kept.
- **Delegation without the `delegate` tool (text mode).** If the coordinator's tools don't load, delegation still works. Causes include Copilot's organisation policy *MCP servers in Copilot* being off ("MCP servers blocked by policy") or Pi, which has no MCP support. In text mode the coordinator writes `DELEGATE role[@harness]: brief` lines, the app runs those specialists in parallel and feeds their results back to it, for up to 6 rounds per request. When the tools are missing after the first reply, the coordinator is asked to re-plan in text mode instead of doing the work itself. The chat says why: blocked by policy (detected from Copilot's logs), Pi, or "run Test tool servers". A troubleshooting entry was added to the Documentation page.
- **TheFlashMaster only coordinates.** It no longer does any work itself, small tasks included. Reading or analysing code and documents, editing files, running commands, reviews and artifacts all go to a specialist through `delegate`. When no specialist fits it uses software-expert for code and analyst for anything else, and it sends incomplete results back as a follow-up instead of fixing them itself. If delegation fails, it reports the failure instead of falling back to doing the work.
- **Fix: background agents not shown as working.** A specialist waiting for a free slot (Settings → Agents → max concurrent turns) used to sit at "idle" with no activity. It now shows as running with "⏳ Queued — N/max agents busy". A specialist the coordinator waits on now runs in the coordinator's slot, so the two can no longer block each other. An agent stopped while queued no longer starts afterwards.
- **Delegation can pick the agent CLI:** `delegate` takes `harness` (copilot, opencode, pi, duo) and `model`, and warns in the chat when the requested CLI isn't available. The coordinator is told never to start agent CLIs from a shell or use its CLI's built-in sub-agents for specialist work. Agents started that way ran outside the app, without its tools ("no filesystem or shell tools exposed") and invisible in the Agents tab.
- **Fix: `ERR_NO_SUPPORTED_PROXIES`.** The proxy value (from Settings or `https_proxy`) is now normalised before Chromium sees it. That covers credentials (`http://user:pass@host:port`, answered on the proxy's sign-in challenge), paths and trailing slashes, `socks5h://` and `socks4a://`, PAC/WPAD URLs (`…/proxy.pac`, `wpad.dat`, `pac:<url>`) and lists of several proxies. When Chromium still rejects the proxy setup, requests fall back to the Windows system proxy, then a direct connection, and keep the mode that works. Settings → Network has a **Test connection** panel that shows the proxy in use and what it resolves to for an address. Copilot, npm and pip get a proper `http://host:port` URL, and never a PAC URL.

- **Fix: renaming a chat** no longer snaps back to the old name while typing. The sidebar row was a component defined inside the render function, so every update (agent status, streaming) remounted the rename field. The rename field now keeps its own state, Enter or clicking away saves, and Esc cancels. The same pattern was fixed in the Documentation page, where open troubleshooting items no longer collapse.
